# Implementation references

- [VirtualMachine_to_OCI-BareMetal](https://github.com/cj667113/VirtualMachine_to_OCI-BareMetal): experimental EFI/native preparation examples. Informs physical NIC, storage-driver and initramfs requirements. Its machine-specific boot addresses, initiator identities, BLS deletion and layout assumptions are not copied into this application.
- [VirtualMachine_to_OCI-VM](https://github.com/cj667113/VirtualMachine_to_OCI-VM): VM preparation examples. Informs VirtIO, generic initramfs, networking and boot-argument adaptation.
- [OCI BYOI requirements and limitations](https://docs.oracle.com/en-us/iaas/Content/Compute/References/bringyourownimage.htm): provider requirements; explicitly states BYOI to bare-metal instances is unsupported. Experimental disk preparation must not be presented as OCI support.
- [OCI Linux image import](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/importingcustomimagelinux.htm) and [custom images](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/managingcustomimages.htm): import and lifecycle requirements.
- [OCI networking types and supported shapes](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/edit-launch-options.htm), [LaunchOptions SDK source](https://github.com/oracle/oci-python-sdk/blob/master/src/oci/core/models/launch_options.py), and [CreateImageDetails SDK source](https://github.com/oracle/oci-python-sdk/blob/master/src/oci/core/models/create_image_details.py): `ACCELERATEDPV` network and launch enums, shape/image eligibility, and the distinction between SDK values and the destination region's capability schema.
- [OCI CPU architecture by shape](https://docs.oracle.com/en-us/iaas/Content/Compute/References/computeshapes.htm), [ARM serial console](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/enablingserialconsoleaccess.htm), and [Linux EFI stub](https://docs.kernel.org/admin-guide/efi-stub.html): ARM64/x86 shape matching, `ttyAMA0` for ARM serial preparation, and architecture-specific EFI kernel prerequisites.
- [Libguestfs architecture boundaries](https://libguestfs.org/virt-builder.1.html#architecture) and [guest command execution](https://libguestfs.org/guestfs.3.html#guestfs_command): filesystem operations can cross guest architectures; running guest programs needs compatible execution. Forge supplies native amd64/arm64 Docker workers and rejects unverified cross-architecture guest execution.
- [OpenSSH server configuration](https://man.openbsd.org/sshd_config) and [cloud-init password configuration](https://docs.cloud-init.io/en/latest/reference/modules.html#set-passwords): SSH configuration precedence, included and conditional settings, authorized-key paths, and the separate password/keyboard-interactive methods. These inform explicit image SSH access changes and guest-side configuration validation.
- [Ubuntu 26.04 LTS changes](https://documentation.ubuntu.com/release-notes/26.04/summary-for-lts-users/), [dracut transition](https://discourse.ubuntu.com/t/spec-switch-to-dracut/54776), and [26.04.1 fixes](https://documentation.ubuntu.com/release-notes/26.04/1/): native dracut detection, compatibility wrappers and current cloud-init behavior. Ubuntu's [dracut-network file inventory](https://packages.ubuntu.com/resolute/all/dracut-network/filelist) uses `74iscsi`; verification follows the installed module and archive hooks instead of assuming an upstream directory number. [Zstandard streaming API](https://github.com/facebook/zstd/blob/dev/lib/zstd.h) informs bounded initramfs decoding; actual VG/LV and filesystem identities drive automatic mount reconciliation.
- [Oracle's VM and bare-metal image preparation guidance](https://blogs.oracle.com/cloud-infrastructure/enabling-external-custom-images-virtual-and-bare-metal): iSCSI firmware discovery, initramfs networking, and Oracle cloud-init discovery. This engineering guidance does not remove the BYOI reference's bare-metal support limitation.
- [dracut iSCSI module setup](https://github.com/dracutdevs/dracut/blob/master/modules.d/95iscsi/module-setup.sh), [command-line hook](https://github.com/dracutdevs/dracut/blob/master/modules.d/95iscsi/parse-iscsiroot.sh) and [firmware handler](https://github.com/dracutdevs/dracut/blob/master/modules.d/95iscsi/iscsiroot.sh): kernel modules, installed userspace, boot hooks and firmware login behavior. Verification follows the handler actually present in each guest archive, including modern `iscsiadm`/`iscsid` implementations.
- [cloud-init first-boot detection](https://docs.cloud-init.io/en/latest/explanation/first_boot.html), [Oracle datasource](https://docs.cloud-init.io/en/latest/reference/datasources/oracle.html), and [datasource implementation](https://github.com/canonical/cloud-init/blob/main/cloudinit/sources/DataSourceOracle.py): new-instance provisioning, network bootstrap and cache-trust limits. Installed cloud-init alone is insufficient evidence for portable networking.
- [Linux 6.12 firmware Kconfig](https://github.com/torvalds/linux/blob/v6.12/drivers/firmware/Kconfig): `CONFIG_ISCSI_IBFT` exposes firmware boot information through sysfs; the firmware-discovery profile requires this driver in addition to iSCSI transport support.
- [libguestfs API](https://libguestfs.org/guestfs.3.html) and [archive implementation](https://github.com/libguestfs/libguestfs/blob/master/daemon/tar.c): isolated filesystem access, GPT/LVM APIs, metadata-preserving archive export/restore and validation.
- [virt-resize](https://libguestfs.org/virt-resize.1.html): direct resize behavior and filesystem limitations.
- [util-linux fstab format](https://man7.org/linux/man-pages/man5/fstab.5.html): UUID/LABEL selectors, escaped spaces/tabs and retained mount options. Label preference uses actual inspected identities and never creates filesystem labels.
- [Oracle Linux XFS documentation](https://docs.oracle.com/en/operating-systems/oracle-linux/9/xfs/xfs-GrowinganXFSFileSystem.html): XFS growth and the absence of in-place shrink.
- [Debian bookworm mkfs.xfs](https://manpages.debian.org/bookworm/xfsprogs/mkfs.xfs.8.en.html): filesystem creation features in the pinned image appliance.
- [systemd unit configuration](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html) and [configuration syntax](https://www.freedesktop.org/software/systemd/man/latest/systemd.syntax.html): system-unit load precedence, aliases, templates, additive dependency directives, drop-ins and enablement links. The offline explorer reads these files through libguestfs; it does not execute systemctl or guest programs. Its graph omits generated/runtime units and implicit dependencies, and does not evaluate conditions.
- [systemd-analyze](https://www.freedesktop.org/software/systemd/man/latest/systemd-analyze.html): `blame` and `critical-chain` rely on runtime activation measurements. Offline dependency exploration supplies neither measured durations nor a measured critical path, and ordering is distinct from activation dependencies.

The user-supplied QCOW2 optimization record additionally informed the new-disk XFS/LVM rebuild, UUID and EFI preservation, zlib QCOW2 output, and the distinction between virtual disk capacity and compressed transfer size. Read-only host audits on 2026-10-28 verified the guest-facing drivers and boot transports described in the [hardware review](docs/oci-compatibility.md#reviewed-e6-ax-vm-and-e5-bare-metal-configurations). The subsequent [VM3 comparison](docs/oci-compatibility.md#vm3-native-image-portability) established unchanged kernel/initramfs/GRUB hashes across a native OCI bare-metal capture and VM launch, and informed preservation checks. A separate [E6 Ax to E5 Flex clone comparison](docs/oci-compatibility.md#e6-ax-to-e5-flex-native-image-portability) confirmed unchanged boot files and shared VirtIO drivers despite different NIC subsystem IDs. It informed VM-to-VM preservation tests and destination shape/network compatibility checks; attachment eligibility comes from Oracle's published shape table, not from guessing a control-plane mode from a guest driver. Private source images, host addresses, raw audit reports and login credentials are not repository fixtures.
